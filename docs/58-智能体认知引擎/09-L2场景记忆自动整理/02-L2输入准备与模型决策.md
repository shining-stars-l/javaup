# L2输入准备与模型决策

## 这一篇从 Job 的哪里开始

上一篇讲到，调度器已经把 L1 当前版本集合冻结到 `HighLevelEvolutionJobSnapshot.input`。后台 worker 认领 Job 后，`JdbcHighLevelEvolutionWork.prepare()` 进入 L2 准备阶段，实际顺序是：

1. 根据目标层级把通用 Job 规范成 `L2_EVOLUTION`。
2. 从 `memory_version` 读取 Job 指定的 L1 当前版本正文。
3. 从 `l2_scenario` 和 `l2_scenario_version` 读取当前活跃场景及当前版本。
4. `ModelRuntimeL2EvolutionModel` 组装 JSON，调用 `SystemMemoryGeneration.Role.L2_EVOLVE`。
5. 严格解析模型输出，得到 `L2PlannedDecision` 列表。
6. 对 MERGE 决策确定稳定的 canonical Scenario。
7. 检查来源闭合、key 唯一、目标属于当前状态、有效场景数不超过 15。

这段代码只准备数据和决策，不写场景表。准备成功以后，`JdbcHighLevelEvolutionExecution` 开启最终提交事务；运行器在事务里复核租约、授权和来源，再写入下一篇要讲的场景发布结果。
