# L2调度与任务创建

## 先来看一下 L2 是从哪里接过来的

L2 不直接监听外部会话，也不从 L0 重新开始。L1 原子记忆发布成功后，会给 `memory-current` 投影追加一条 L1 `UPSERT` 变化。高层运行器每秒轮询一次这些变化，等 30 秒防抖时间过去，再把当前所有活跃 L1 Atom 的当前版本交给 L2。

我把这一段拆成 6 步，小伙伴先记住顺序，后面再看每个方法里的判断：

1. L1 发布写入 `projection_change`，记录本次 L1 当前版本变化。
2. `JdbcHighLevelAutomaticSchedulingStore.candidates()` 按 L2 游标找到还没消费的变化。
3. `DefaultHighLevelAutomaticScheduling.scheduleDue()` 过滤 30 秒防抖窗口，并读取记忆库授权版本。
4. `DefaultL2EvolutionScheduling.schedule()` 排序 L1 版本 ID，计算输入摘要，创建或复用 L2 Job。
5. `JdbcL2EvolutionSchedulingStore.create()` 再次确认这些版本仍属于当前记忆库的活跃 L1 Atom。
6. `JdbcHighLevelAutomaticSchedulingStore.register()` 在事务里登记运行态并推进高层游标。
