# L2租约执行与失败恢复

## L2 Job 怎样从 PENDING 走到终态

L2 Job 创建完成后，`DefaultHighLevelEvolutionRuntime` 每秒执行一次 `cycle()`。一轮 cycle 最多认领并处理一个 Job，执行顺序固定为：

1. 回收已经过期的租约。
2. 发现并登记新的 L2/L3 候选。
3. 从数据库认领一条可执行 Job，生成 Attempt 和 fencing token。
4. 在模型准备期间每 15 秒发送一次 heartbeat。
5. 在事务外准备 L2 决策，再进入提交事务，复核租约、授权和来源后写库。
6. 成功时把 Job 和 Attempt 改为 `SUCCEEDED`；失败时按错误类型进入 `FAILED_RETRYABLE` 或 `DEAD_LETTER`。
