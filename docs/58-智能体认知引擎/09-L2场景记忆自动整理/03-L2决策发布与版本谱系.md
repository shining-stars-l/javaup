# L2决策发布与版本谱系

## 发布从哪里开始

上一篇的 `DefaultL2EvolutionProcessing.prepare()` 已经得到：

- Job 冻结的 L1 来源版本；
- 处理开始时的当前 L2 Scenario 快照；
- 模型生成并通过校验的 `L2PlannedDecision`；
- 本次 `L2_EVOLVE` 调用的 generation facts。

生产路径由 `JdbcHighLevelEvolutionExecution.execute()` 在模型准备结束后开启最终提交事务。`JdbcL2EvolutionProcessing.JdbcPublisher.publish()` 使用同一数据源，加入这个已有事务，写入场景结果；后续 Job 成功状态也在这笔事务里更新。场景发布的顺序是：

1. 回查每个当前 Scenario 的历史版本。
2. 用这些历史版本初始化 `DefaultL2EvolutionPublisher` 的 staged state。
3. 按决策顺序生成 Scenario、Version、Lineage 或 Proposal 结果。
4. 把 staged 结果写入 `l2_scenario`、`l2_scenario_version`、`high_level_lineage`、`high_level_memory_proposal`。
5. 通过 revision 条件更新当前 Scenario，写入 `projection_change`。
6. 任意一步抛错，整笔事务回滚，Job 不会被标记为成功。
