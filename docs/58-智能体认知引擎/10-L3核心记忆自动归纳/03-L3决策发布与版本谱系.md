# L3决策发布与版本谱系

## 发布从哪里开始

上一篇的 `DefaultL3EvolutionProcessing.prepare()` 已经得到四样东西：

- Job 冻结的 L2 来源版本和正文；
- 处理开始时的当前 L3 Core 快照；
- 通过 JSON、来源闭合和决策形状校验的 `L3PlannedDecision`；
- 本次 `L3_SYNTHESIZE` 调用的 `L3GenerationFacts`。

真正的发布入口是 `JdbcL3EvolutionProcessing.JdbcPublisher.publish()`。它在一个数据库事务里按下面的顺序工作：

1. 按 `job_id` 查询是否已经有 L3 lineage，命中就组装回放结果。
2. 读取当前 Core 的历史版本，初始化发布器的 staged state。
3. 根据 CREATE、UPDATE、SKIP 计算 Core、Version、Lineage 和 Proposal 结果。
4. 将计算结果写入 `l3_core`、`l3_core_version`、`high_level_lineage`、`high_level_lineage_source`，需要人工审核时再写 `high_level_memory_proposal`。
5. 自动 UPDATE 用 Core revision 做 CAS，确认当前指针没有被并发修改。
6. 事务成功返回 `Succeeded`，外层高层执行器随后才把 Job 和 Attempt 标记为成功。
