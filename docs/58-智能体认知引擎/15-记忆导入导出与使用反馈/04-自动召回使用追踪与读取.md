# 自动召回使用追踪与读取

## 先把“使用追踪”给说准确了

自动召回先准备记忆结果，再写一条 trace，最后才构造响应交给 HTTP 层。这条记录包括本次准备的版本、token 数、截断和 stale 情况，以及召回耗时。它的阶段固定为 `SERVER_PREPARED`。

小伙伴看到 trace 时，可以确认服务端准备过这份结果。客户端是否收到响应、是否把上下文交给外部模型、模型是否采用某条记忆，还需要各自的证据。下面会看到，trace 写完以后，后端也可能因为授权变化或超时返回降级响应。

本篇按 `AutomaticMemoryController → AutomaticMemoryAdapter → ExternalMemoryUsageTraces` 追执行顺序，再讲 trace 查询，以及自动采集怎样通过 `TrustedRecallTraceResolver` 复核关联。候选检索和排序由 `MemoryRecall` 完成，本目录集中展开与使用追踪有关的包装、记录和校验。
