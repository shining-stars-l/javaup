# 记忆导出与导入包校验

## 我先把这条流程分成两个动作

小伙伴可以把导出理解成“把当前能读取的记忆整理成一份 JSON 包”，把导入理解成“从包里挑出有效的 L1，交给记忆库负责人审核”。这两个动作都要重新检查当前权限。导入结束后得到的是候选和批次收据，接受候选以后才会生成新的人工 L1。

这一篇沿着 MCP 工具往里看。后端源码根目录是 `/Applications/java/idea_work_my/gitee/agent-up-memory`，下面的路径都相对于这个目录。

| 源码位置 | 本篇要跟的方法 |
| --- | --- |
| `bootstrap/.../mcp/McpSharedMemoryToolExecutor.java` | `context`、`exportMemory`、`importMemory` |
| `memory-evolution/.../api/SharedMemoryPortability.java` | `Export`、`Import`、`ImportReceipt` |
| `memory-evolution/.../internal/JdbcSharedMemoryPortability.java` | 导出、导入、候选抽取、摘要计算 |
| `workspace-governance/.../internal/JdbcMemoryContentGovernanceAuthority.java` | 目标资产的内容治理锁 |

`MemoryEvolutionAutoConfiguration` 把 workspace 读接口、项目治理、项目资格和 L1/L2/L3 读模型装配给 `JdbcSharedMemoryPortability`。`McpHttpConfiguration` 再把 `SharedMemoryPortability` 交给 MCP 执行器。这样 bootstrap 通过 `api` 调用业务模块，不直接引用它的 JDBC 实现。
