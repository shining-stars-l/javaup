# 导入候选审核与生命周期

## 审核先决定内容，再决定是否发布

前一篇把包里的 ACTIVE L1 转成了导入候选。负责人可以先修改候选的类型和正文，再接受它。接受成功后，目标库会得到一个新的人工 L1，候选保存这个 Atom 的 ID；拒绝则只结束审核，不生成 Atom。

本篇按 `SharedMemoryImportReviewController → SharedMemoryImportReview → JdbcSharedMemoryImportReview → L1ManualGovernance → JdbcL1ManualGovernance` 继续往里追。涉及下层的创建、失效和删除，我会在调用的位置把源码展开，小伙伴不用跳到另一篇才能把这一轮执行看完。
