# L1原子记忆发布、版本与谱系

## 发布事务从哪里开始

上一篇的 `DefaultL1EvolutionProcessing` 已经得到一组 `L1PublicationDecision`。真正写库的是 `JdbcL1EvolutionProcessing.JdbcPublisher.publish()`。它把下面的动作放进同一个数据库事务：

1. 再次确认 Job Lease、worker、Attempt 和 fencing token 仍然有效。
2. 复核当前 memory asset 的治理 revision，确认项目权限没有在模型调用期间变化。
3. 锁定并核对本 Job 的 L0 输入仍然完整。
4. 保存两次模型调用的配置快照和 generation facts。
5. 按 decision 顺序写 Atom、Version、Lineage、处理决定、合并来源和 projection change。
6. 把 Job 标成 `SUCCEEDED`，同时推进 `l1_success_cursor`。
7. 立即执行延迟约束，让数据库在事务提交前检查整批事实是否闭合。
