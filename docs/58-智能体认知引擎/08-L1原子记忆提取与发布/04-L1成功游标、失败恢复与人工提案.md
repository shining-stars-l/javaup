# L1成功游标、失败恢复与人工提案

## 先看成功和失败的范围边界

L1 Job 只有在下面几件事都于同一事务完成后，才会进入 `SUCCEEDED`：

- 两个模型角色的配置快照和 generation facts 已落库；
- 每个候选都有一条决定记录；
- `STORE`、`UPDATE`、`MERGE` 的输出版本和 Lineage 已建立；
- `MERGE` 的被吸收 Atom 已经是 `MERGED`；
- `l1_success_cursor` 已推进到本 Job 的最后一条 source；
- 当前 Attempt 仍然持有有效 fencing token。

如果中途出错，成功游标不会前进。后续重试仍使用同一份 Job input，不会跳过这批消息。错误是可重试的，Job 进入 `FAILED_RETRYABLE`；错误属于输入、配置或模型输出合同问题，Job 最终进入 `DEAD_LETTER`。
