# 用户注册登录与认证会话

## 先看完整调用链

这一篇开始，我们从 `/api/v1/auth/register`、`/api/v1/auth/login` 和 `/api/v1/auth/activate` 进来，顺着 Spring MVC、身份过滤器、`identity-access` 模块和 PostgreSQL 一路走到 `AuthenticatedPrincipal`。

项目把浏览器登录态当成一条独立的 Authentication Session。浏览器拿到的是 `sessionId.secret`，数据库只保存 secret 的摘要；后续请求还要重新查库确认会话没有过期、用户没有停用、credential epoch 没有变化。这样，管理员停用用户或重置凭据后，旧 Cookie 不会继续生效。

```text
POST /api/v1/auth/register|login|activate
  -> IdentityAuthenticationController
     -> IdentityAuthentication.register/login/activate
        -> JdbcIdentityAuthentication
           -> 规范化输入、校验密码
           -> 事务内读写 app_user / one_time_credential
           -> 创建 authentication_session
           -> 返回一次性 session.secret
     -> IdentityHttpSupport.issueSessionCookie
  -> 后续受保护请求
     -> IdentityAuthenticationFilter
        -> 解析 AUM_SESSION 或 Authorization: Bearer
        -> authenticateSession / authenticateToken
        -> 写入 request principal
        -> 浏览器写请求做 Origin + CSRF 校验
        -> 放行到 Controller
```
