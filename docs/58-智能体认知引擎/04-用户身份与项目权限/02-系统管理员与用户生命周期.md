# 系统管理员与用户生命周期

## 请求从哪里进来

系统管理员接口位于 `/api/v1/system/users`。这一组接口看起来像普通 CRUD，实际每个写操作都要经过三层检查：请求必须来自浏览器 Authentication Session；这个会话本身必须仍然有效，并且最近完成过重新认证；当前用户还要拥有未撤销的系统管理员授权。

我把这条链拆开讲，重点看“谁能操作”“操作改变了哪些身份事实”“旧凭据为什么会一起失效”。

```text
HTTP /api/v1/system/users/**
  -> IdentityAuthenticationFilter
     -> 校验 AUM_SESSION
     -> request.setAttribute(PRINCIPAL_ATTRIBUTE, principal)
  -> SystemAdministrationController
     -> requireBrowserSession(request)
     -> IdentityAdministration 命令
  -> JdbcIdentityAdministration
     -> requireAdministrator(actor)
        -> 锁定 session + app_user
        -> 检查 active、epoch、过期时间、重新认证窗口
        -> 检查 system_administrator_grant
     -> 在事务中修改用户和凭据
     -> 写 SecurityAudit
```
