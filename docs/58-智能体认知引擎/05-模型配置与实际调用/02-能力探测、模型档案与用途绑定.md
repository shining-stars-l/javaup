# 能力探测、模型档案与用途绑定

## 保存模型名称，不等于模型已经能用

供应商配置通过后，只是知道“请求该发到哪里”。后端还需要一个模型档案，说明远端模型 ID、模型用途、上下文窗口、输出上限、Tokenizer 和能力声明。

项目现在只开放两种用途：

| 用途 | 使用位置 | 必要能力 |
| --- | --- | --- |
| `MEMORY_GENERATION` | L1 提取、L1 去重、L2 整理、L3 归纳 | 结构化输出 |
| `EMBEDDING` | 记忆向量化和向量查询 | 向量接口、固定维度 |

`ModelProfileGovernance.Draft` 会检查名称、远端模型 ID、上下文窗口、最大输出 Token 和用途能力是否相互匹配。比如 `EMBEDDING` 必须带向量维度，`MEMORY_GENERATION` 不能顺手带一个 embedding 维度。这个检查让后面组装 `EmbeddingRuntimeCommand` 时不用猜模型到底是哪一类。
