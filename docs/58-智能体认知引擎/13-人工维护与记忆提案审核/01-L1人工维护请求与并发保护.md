# L1人工维护请求与并发保护

## 先把人工维护的七种操作认识全了

L1 原子记忆提供七种人工操作。入口都在 `MemoryEvolutionController`，统一交给 `L1ManualGovernance.execute()`：

| 操作 | HTTP 路径 | 是否生成新正文版本 | 主要结果 |
| --- | --- | --- | --- |
| 创建 | `POST /api/v1/memory-assets/{memoryAssetId}/l1` | 是 | 新 Atom、版本 1、人工谱系 |
| 编辑 | `POST .../l1/{atomId}/edit` | 是 | 追加版本，Atom 指向新版本 |
| 失效 | `POST .../l1/{atomId}/invalidate` | 否 | 生命周期改为 `INVALIDATED` |
| 恢复 | `POST .../l1/{atomId}/reactivate` | 否 | 生命周期改回 `ACTIVE` |
| 删除 | `POST .../l1/{atomId}/delete` | 否 | 生命周期改为 `DELETED`，写 Tombstone |
| 回滚 | `POST .../l1/{atomId}/rollback` | 是 | 复制历史正文，追加一个新版本 |
| 合并 | `POST .../l1/merge` | 是 | canonical 追加版本，被吸收项转为 `MERGED` |

这些路径只负责接收请求。负责人权限、并发校验、写库和索引通知都在 `JdbcL1ManualGovernance` 的同一事务里完成。
