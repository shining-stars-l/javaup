# 失败任务人工重试与取消

## 人工操作从处理任务接口开始

后台会自动领取可重试任务。遇到配置错误死信，负责人修好模型用途绑定后，可以人工让原 Job 重新排队；遇到不需要继续处理的输入，也可以取消任务。

这两个动作沿着同一条后端链执行：HTTP 组装命令 → JDBC 事务 → 当前资产治理授权 → 幂等回执 → Job revision → 重试或取消 → 条件写库 → 记录首次结果。我按这条顺序讲，避免把“按钮已经点过”与“数据库动作已经成功”混在一起。

| 接口 | 用途 | 关键输入 |
| --- | --- | --- |
| `GET /api/v1/memory-processing` | 分页查处理任务 | 可选资产、状态、cursor、limit |
| `GET /api/v1/memory-processing/{jobId}` | 查 Job 与尝试状态 | Job ID |
| `POST /api/v1/memory-processing/{jobId}/retry` | 人工重试 | 幂等键、expectedJobRevision、reason |
| `POST /api/v1/memory-processing/{jobId}/cancel` | 人工取消 | 幂等键、expectedJobRevision、reason |

这里只讲服务端调用，不展开页面。查询与写入响应使用 `no-store`，减少缓存返回旧任务状态的情况。
