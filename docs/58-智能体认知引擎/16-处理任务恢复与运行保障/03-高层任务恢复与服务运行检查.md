# 高层任务恢复与服务运行检查

## 高层任务多了来源和目标 revision 两个检查

L2、L3 的后台任务也会遇到进程退出、模型超时和权限变化。它们有自己的 high_level_evolution_job、runtime 与 Attempt 表，不能直接套用 L1 的每个分支。

除了 Attempt、worker 和 fencing token，高层租约还保存 sourceRevision、targetRevision。模型运行期间，来源可能变化，目标也可能被人工维护；最终发布前必须重新验证。

我沿一轮高层任务展开：回收过期租约 → 调度并领取 → 独立心跳 → 事务外准备 → 短事务提交 → 失败登记。最后再看应用关闭与 readiness，它们能说明服务运行到哪一步。
