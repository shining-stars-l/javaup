# 文本代际索引重建与水位追平

## 先把“代际”这个东西给讲明白

Recall 的文本索引不是一份文件从头写到尾。每个 projection family 都有一个 active generation，必要时再建一个 rebuilding generation。旧代际还没切走之前继续服务读取，新代际在后台慢慢构建，最后一次性切换。

我把普通追平和重建放在同一篇，是因为它们最后都要完成同一件事：让“磁盘上的 Lucene commit 水位”和“PostgreSQL 记录的 active source watermark”指向同一事实。

本篇只讨论后端索引，不讨论 `ComposedMemoryRecall` 如何融合 BM25、Embedding 和稳定记忆。召回编排会在第 12 目录继续讲。
