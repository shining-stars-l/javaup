# 投影变更事实与索引输入

## 这篇文档讲到哪里

我先把范围说清楚：本篇只讲后端如何把“当前记忆变了”记录下来，再交给 Recall 的索引流水线。前端页面、MCP 工具和最终召回上下文组装不在这里展开。

从调用顺序看，链路是这样的：

1. L0 捕获、L1 发布或 L2 发布在自己的权威事务里改变当前状态。
2. 同一事务调用 `JdbcProjectionChangeWriter.append()`，为对应 family 分配连续的 `source_sequence`。
3. 事务同时写入 `projection_change` 和 `projection_outbox`。事务提交前，Recall 看不到这条变化。
4. Recall 通过 `MemoryProjectionSource.readAfter()` 读取事件，`JdbcProjectionInbox` 把无正文事件写进本地 inbox。
5. 索引器后面处理 UPSERT/DELETE 时，再调用 `findCurrent()` 回到 memory-evolution 读取正文和当前版本。
