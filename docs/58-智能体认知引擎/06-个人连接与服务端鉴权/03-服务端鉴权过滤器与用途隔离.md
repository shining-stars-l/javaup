# 服务端鉴权过滤器与用途隔离

## 同一个服务有两类请求凭据

Agent-Up-Memory 的后端同时服务两种调用者：

- **浏览器控制台**：使用 `AUM_SESSION` Cookie，写操作还要通过 Origin 和 CSRF 校验；
- **外部客户端**：使用 `Authorization: Bearer tokenId.secret`，不能拿浏览器 Cookie 访问 MCP、自动召回或自动采集。

两者最后都会变成 `AuthenticatedPrincipal`，但通道不同：浏览器是 `AUTHENTICATION_SESSION`，外部客户端是 `API_TOKEN`。后续模块只看 principal 和 scope，不直接接触 Cookie 或 Authorization 字符串。

```text
普通 /api/v1/**
  -> IdentityAuthenticationFilter（+20）
     -> 解析 Cookie 或 Bearer（二选一）
     -> authenticateSession / authenticateToken
     -> 写 request principal
     -> 浏览器写请求检查 Origin + CSRF

/mcp/v1/**
  -> McpAuthenticationFilter（+10）
     -> 只接受一个 Bearer，拒绝任何 Cookie
     -> authenticateToken
     -> requireCurrentCredential
     -> 写 MCP principal

上述过滤器之后
  -> ExternalConnectionPurposeFilter（+30）
     -> URL 用途必须和 profile.connection_type 一致
     -> 进入 Controller 或 MCP Server
```
