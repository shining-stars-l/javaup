# 连接令牌轮换、撤销与凭据保管

## 为什么要把“连接身份”和“Token”分开

个人连接有一个稳定的 `connectionId`，Token 则可以随着轮换不断变化。客户端安装配置通常绑定的是这条连接和项目，轮换时只替换 secret，不应该让服务端把它当成一条全新的项目连接。

数据库里会出现这样的关系：

```text
connectionId = C1
  ├─ Token T1（旧凭据，可能处于轮换重叠窗口）
  └─ Token T2（当前凭据，profile 继承 C1）
```

这样做有两个实际好处：

- 轮换不会丢掉项目、默认记忆库和用途绑定；
- 撤销时可以沿着同一个 `connectionId` 找到旧 Token 和新 Token，一起阻断。
