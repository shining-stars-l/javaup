# 记忆召回维护与迁移

记忆生产完成后，项目还有一大段工作要做：让工具能稳定找到它、让人工能改它、让旧来源变化时能处理它、让内容能在项目之间迁移。`记忆投影与检索索引～记忆导入导出与使用反馈` 目录都围绕这件事展开。

## 先看发布结果怎样进入索引

详细内容在[记忆投影与检索索引](/agent-up-memory/memory-indexing/projection-change-and-input)。这里先记住一个原则：**权威记忆与查询索引各有用途，不能混着理解。**

记忆发布事务会追加变化事实，说明哪个记忆、哪个版本发生了什么操作。索引 worker 消费这些变化，把当前内容写入文本索引或向量索引。索引处理会保存自己的代次和水位，因此可以知道：

- 当前索引读到了哪一条变化；
- 磁盘上的索引属于哪一代；
- 这条索引内容对应哪个记忆版本和向量空间；
- 中途崩溃后从哪里继续，是否需要重建。

### 文本索引和向量索引各自解决什么问题

文本索引更适合按词、短语和结构查找；向量索引更适合按意思相近的表达查找。两者都只保存查询所需的投影，真正交付前还要回权威表确认版本、状态、项目范围和正文。

索引追平通常先处理增量；代次不一致、出现缺口或校验失败时，会用稳定快照重建新索引，追平变化，完成检查后再切换。旧索引在新索引没准备好前继续提供服务，避免一次重建把整个召回功能切断。
