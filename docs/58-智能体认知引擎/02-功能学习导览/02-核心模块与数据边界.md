# 核心模块与数据边界

第一次打开项目时，很容易被一堆模块和接口名称吓到。我建议先按“它负责哪件事”来认识代码，不要先背目录名。这个后端把一件记忆从接收、整理到使用拆开了，每个模块保存自己最清楚的那部分事实，再通过公共接口把结果交给下一段。

## 先看各模块负责什么

项目根目录的 Maven 聚合包含七个后端模块。`bootstrap` 是运行入口，其他模块提供可复用的业务能力。

| 模块 | 用大白话说它负责什么 | 学习时要抓住的重点 |
| --- | --- | --- |
| `bootstrap` | 启动应用，接收浏览器、MCP 和自动采集请求，把结果转换成 HTTP 响应 | 请求从哪里进来，认证和错误怎样在入口处收口 |
| `identity-access` | 管用户、登录会话、API Token 和身份信息 | 请求是谁发的，凭据现在是否仍然有效 |
| `workspace-governance` | 管团队、项目、项目范围和使用资格 | 这个人能不能使用这个项目，能看到哪个记忆库 |
| `model-runtime` | 管供应商、密钥、模型能力和实际 Chat/Embedding 调用 | 这次调用使用哪个已确认的模型，返回结果怎样校验 |
| `memory-evolution` | 管 L0、L1、L2、L3、任务、版本、来源和人工提案 | 记忆怎样生成、发布、修改、失效和留下历史 |
| `memory-recall` | 管投影、文本/向量索引、候选融合和召回结果 | 索引怎样跟上权威内容，哪些候选能交付给工具 |
| `security-audit` | 记录安全相关操作和审计信息 | 关键动作发生过什么，出了问题能不能追溯 |

这些模块不等于七个必须独立部署的服务。当前项目由 `bootstrap` 组装到同一个后端进程里。阅读时把它们当成七个工作台面，会比把它们想成七套系统更准确。
