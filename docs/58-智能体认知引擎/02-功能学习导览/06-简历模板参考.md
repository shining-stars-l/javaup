# 简历模板参考

这篇给准备把 Agent Up Memory 写进简历的小伙伴用。项目内容比较多，简历里不要把所有技术名词都塞进去，挑自己真正看过源码、能讲清楚设计原因和异常处理的 4～6 个点就够了。

## 一、先想清楚简历怎么写

Agent Up Memory 的重点在于把一轮外部对话变成可以追踪、可以检索、可以人工维护、出了问题还能恢复的长期记忆。写简历时，建议围绕这条主线组织内容：

```text
外部会话接入
    ↓
身份、连接、项目范围复核
    ↓
L0 原始底稿落库
    ↓
L1 原子记忆提取
    ↓
L2 场景记忆、L3 核心记忆逐级整理
    ↓
文本/向量索引投影
    ↓
memory_search / memory_recall / MCP 交付
    ↓
人工治理、来源协调、反馈和任务恢复
```

简历上的每个技术点都应该能回答三个问题：

1. 当时要解决什么实际问题？
2. 代码里采用了什么处理顺序，关键判断在哪里？
3. 如果模型超时、请求重放、权限变化或 worker 退出，系统会怎样收口？

:::info 简历篇幅建议
项目描述控制在 150～200 字左右；负责内容选择 4～6 项重点展开。没有亲自验证过的性能数字、准确率和线上规模不要写，源码里有的状态、版本、租约和审计事实可以放心写。
:::
