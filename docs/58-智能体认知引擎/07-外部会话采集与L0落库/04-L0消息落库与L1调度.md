# L0消息落库与L1调度

## 从“已接收”到“可以提取”

上一篇讲到新轮次已经通过 tombstone、幂等和版本判断，并成功插入 `external_turn`。接下来同一个事务要把这轮对话补齐：

1. 更新外部会话的 `updated_at`。
2. 写入 USER 和 ASSISTANT 两条 `external_message`。
3. 写入一条 `external_turn_receipt`，让客户端可以查询接收结果。
4. 保存可信的召回 trace 和 delivery。
5. 把两条消息投影成两条 L0：用户消息只审计，助手消息允许提炼。
6. 写入 `successful_l0_source`，追加投影变更，并请求 L1 调度。

整个过程仍在 `JdbcExternalTurnCapture.capture()` 的事务里。只要中间任意一条 SQL 失败，收据、消息、L0 和成功来源标记会一起回滚。
