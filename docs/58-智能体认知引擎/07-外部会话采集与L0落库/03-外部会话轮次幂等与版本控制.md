# 外部会话轮次幂等与版本控制

## 采集事务先解决重复和顺序

上一阶段已经拿到了可信的 `ExternalTurnCapture.Command`。接下来进入 `JdbcExternalTurnCapture`，这里会把一次完成的外部轮次变成可追踪的数据库事实。

这一段最容易出错的地方有两个：

- 客户端可能因为网络重试，把同一轮提交多次。
- 客户端可能先提交修订版，或者重复使用同一个 `sourceTurnId` 提交不同正文。

所以数据库写入前要按下面顺序处理：

1. 检查来源是否命中过去的删除 tombstone。
2. 按项目、客户端类型、客户端实例和原生会话 ID 找到或创建外部会话，并锁住绑定。
3. 按 `sourceTurnId + sourceRevision` 查询已有轮次，决定重放还是新建。
4. 如果是新版本，锁住旧版本并检查只能逐次递增。
5. 创建新轮次、两条消息、收据和后续 L0 来源。
