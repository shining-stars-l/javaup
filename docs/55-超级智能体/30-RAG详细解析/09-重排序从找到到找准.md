# 重排序：从"找到"到"找准"

## 召回了一堆，但排序不对

前面几篇咱们把检索这块讲得差不多了——向量检索理解语义，BM25 精确匹配，混合检索取长补短。跑下来效果看起来不错，召回的候选集里确实包含了正确答案。

但这里有个问题：**召回了不等于排对了**。

举个例子。假设你在给律所搭一个合同审查助手，律师问：`股权转让协议中，竞业禁止条款的有效期限制是多久？`

混合检索返回了 10 个候选结果：

- Top-1：股权转让协议范本概述
- Top-2：公司法关于竞业禁止的一般规定
- Top-3：**股权转让中竞业禁止条款有效期：不超过2年**（这才是正确答案）
- Top-4：劳动合同竞业限制相关规定
- Top-5：股权激励协议模板
- ...

正确答案在 Top-3，但大模型的上下文窗口通常只会塞 Top-3 或 Top-5 的内容。如果你只取 Top-1 和 Top-2，律师就拿不到想要的答案。

问题出在哪？**召回阶段追求的是"尽可能把相关的都找出来"，但排序不一定精准**。

## 选秀节目复活赛的启发

这个问题让我想起了选秀节目。

初选阶段，评委要从几千个选手里选出 100 个进入复赛。这个阶段追求的是"不漏掉有潜力的选手"，宁可多选一些，也不能把真正的好苗子刷掉。

复赛阶段就不一样了。100 个选手要选出 10 个进入决赛，评委会仔细看每个人的表演、点评、投票，精挑细选。这个阶段追求的是"把最好的几个选出来"。

RAG 里的检索也是这个道理：

- **召回阶段**（向量检索/BM25/混合检索）像初选，追求覆盖面广、不漏掉相关结果
- **重排序阶段**（Reranking）像复赛，对候选集精挑细选，把最相关的排到最前面

很多 RAG 系统只做了初选，没做复赛，所以答案质量上不去。

## 为什么需要专门的重排序

你可能会问：召回阶段不是已经有分数了吗？按分数排不就行了？

问题在于，召回阶段的排序模型和重排序模型是两种完全不同的设计：

### Bi-Encoder vs Cross-Encoder

**Bi-Encoder（双编码器）**——召回阶段用的

工作方式：Query 和 Document 分别编码成向量，然后计算向量相似度。

```
Query → [Encoder] → Query向量
Document → [Encoder] → Doc向量
相似度 = cosine(Query向量, Doc向量)
```

优点：速度快。Document 向量可以提前算好存起来，查询时只需要编码 Query，然后做向量比对。

缺点：精度有限。Query 和 Document 是独立编码的，模型看不到它们之间的交互关系。

**Cross-Encoder（交叉编码器）**——重排序用的

工作方式：把 Query 和 Document 拼接在一起，一起输入模型，模型能看到完整的交互，输出一个相关性分数。

```
[CLS] Query [SEP] Document [SEP] → [Encoder] → 相关性分数
```

优点：精度高。模型能捕捉 Query 和 Document 之间的细粒度语义关系。

缺点：速度慢。每个 (Query, Document) 对都要过一遍模型。

### 为什么不直接用 Cross-Encoder 做检索

你可能又会问：既然 Cross-Encoder 精度更高，为什么不直接用它做检索？

因为太慢了。

假设你的知识库有 100 万个文档，用户每次提问，你要把这 100 万个文档逐个和 Query 拼接起来过 Cross-Encoder。就算每个只要 10ms，总共也要 10000 秒，用户等到花儿都谢了。

所以工程上一定是两阶段策略：

1. **粗召回**（Bi-Encoder）：快速从 100 万个文档中召回 Top-20 或 Top-50，延迟低
2. **精排序**（Cross-Encoder）：对这 20~50 个候选逐个打分，延迟可接受，精度高

这就是"快召回 + 慢精排"的核心思想。

## 常用的 Reranker 模型

目前主流的几个 Reranker 模型：

| 模型 | 特点 | 中文效果 | 推荐场景 |
|:-----|:-----|:---------|:---------|
| BAAI/bge-reranker-v2-m3 | 轻量、稳定、部署灵活 | 好 | 预算敏感、快速上线 |
| Qwen/Qwen3-Reranker-8B | 长文本强、支持指令定制 | 很好 | 复杂意图、行业问答 |
| Cohere rerank-v4.0 | 商业 API、集成体验好 | 一般 | 海外产品、多语言 |
| jina-reranker-v2-base-multilingual | 多语言支持好 | 好 | 跨语言场景 |

对于中文场景，推荐 `bge-reranker-v2-m3` 或 `Qwen3-Reranker-8B`。前者轻量快速，后者效果更好但成本稍高。

咱们用"合同审查助手"这个场景来跑一遍重排序的完整流程。

```java
/**
 * 合同审查助手 - 重排序实现
 * 演示混合检索 + Reranker精排的完整流程
 */
public class ContractReviewReranker {

    private static final String RERANK_API_KEY = "你的SiliconFlow API Key";
    private static final String RERANK_URL = "https://api.siliconflow.cn/v1/rerank";
    private static final String RERANK_MODEL = "BAAI/bge-reranker-v2-m3";

    private static final Gson GSON = new Gson();
    private static final OkHttpClient HTTP_CLIENT = new OkHttpClient();

    /**
     * 重排序结果
     */
    @Data
    @AllArgsConstructor
    public static class RerankResult {
        private int originalIndex;      // 原始排名
        private double relevanceScore;  // 重排序分数
        private String content;         // 文档内容
        private String source;          // 来源
    }

    public static void main(String[] args) throws Exception {
        // 模拟混合检索返回的候选结果（实际项目中从Milvus获取）
        String query = "股权转让协议中，竞业禁止条款的有效期限制是多久";

        List<Map<String, String>> candidates = List.of(
                Map.of(
                        "content", "股权转让协议是股东之间转让股权的法律文件，需要明确转让价格、付款方式、交割时间等核心条款。",
                        "source", "股权转让/概述.md"
                ),
                Map.of(
                        "content", "根据《公司法》规定，公司高管和核心员工的竞业禁止义务一般在离职后生效，用人单位应支付经济补偿。",
                        "source", "公司法/竞业禁止.md"
                ),
                Map.of(
                        "content", "股权转让协议中的竞业禁止条款，限制转让方在一定期限内不得从事与目标公司相竞争的业务。根据司法实践，该期限一般不超过2年，超过部分可能被认定为无效。",
                        "source", "股权转让/竞业禁止条款.md"
                ),
                Map.of(
                        "content", "劳动合同中的竞业限制条款适用于用人单位与劳动者之间，期限不得超过二年，且需支付竞业限制补偿金。",
                        "source", "劳动法/竞业限制.md"
                ),
                Map.of(
                        "content", "股权激励协议是公司为激励核心员工而授予其股权的协议，通常包含服务期限、行权条件、回购条款等内容。",
                        "source", "股权激励/概述.md"
                ),
                Map.of(
                        "content", "竞业禁止条款的效力认定需要综合考虑：(1)是否有合理的商业利益保护需要 (2)限制范围是否合理 (3)期限是否适当 (4)是否有对价补偿",
                        "source", "合同法/竞业禁止效力.md"
                ),
                Map.of(
                        "content", "股权转让的税务处理：个人转让股权需缴纳个人所得税，税率为20%；企业转让股权需缴纳企业所得税。",
                        "source", "股权转让/税务处理.md"
                ),
                Map.of(
                        "content", "转让方承诺在股权转让完成后2年内，不得直接或间接从事与目标公司主营业务相同或相似的业务，违反本条款需支付违约金。",
                        "source", "股权转让协议/模板第八条.md"
                )
        );

        System.out.println("========== 重排序前 ==========");
        System.out.println("问题：" + query);
        System.out.println();

        for (int i = 0; i < candidates.size(); i++) {
            Map<String, String> doc = candidates.get(i);
            System.out.printf("Top-%d [%s]%n", i + 1, doc.get("source"));
            System.out.println("     " + truncate(doc.get("content"), 60));
        }

        // 执行重排序
        List<RerankResult> reranked = rerank(query, candidates, 5);

        System.out.println();
        System.out.println("========== 重排序后 ==========");

        for (int i = 0; i < reranked.size(); i++) {
            RerankResult result = reranked.get(i);
            System.out.printf("Top-%d [%.4f] 原排名:%d [%s]%n",
                    i + 1, result.getRelevanceScore(),
                    result.getOriginalIndex() + 1, result.getSource());
            System.out.println("     " + truncate(result.getContent(), 60));
        }

    /**
     * 调用Reranker API进行重排序
     */
    public static List<RerankResult> rerank(String query,
                                            List<Map<String, String>> candidates,
                                            int topN) throws Exception {
        // 提取文档内容
        List<String> documents = candidates.stream()
                .map(c -> c.get("content"))
                .toList();

        // 构建请求体
        JsonObject body = new JsonObject();
        body.addProperty("model", RERANK_MODEL);
        body.addProperty("query", query);
        body.add("documents", GSON.toJsonTree(documents));
        body.addProperty("top_n", topN);
        body.addProperty("return_documents", true);

        Request request = new Request.Builder()
                .url(RERANK_URL)
                .addHeader("Authorization", "Bearer " + RERANK_API_KEY)
                .addHeader("Content-Type", "application/json")
                .post(RequestBody.create(GSON.toJson(body),
                        MediaType.parse("application/json")))
                .build();

        try (Response response = HTTP_CLIENT.newCall(request).execute()) {
            if (!response.isSuccessful()) {
                throw new RuntimeException("Rerank API调用失败: " + response.code());
            }

            String respBody = response.body().string();
            JsonObject json = GSON.fromJson(respBody, JsonObject.class);
            JsonArray results = json.getAsJsonArray("results");

            List<RerankResult> reranked = new ArrayList<>();
            for (JsonElement element : results) {
                JsonObject item = element.getAsJsonObject();
                int index = item.get("index").getAsInt();
                double score = item.get("relevance_score").getAsDouble();

                reranked.add(new RerankResult(
                        index,
                        score,
                        candidates.get(index).get("content"),
                        candidates.get(index).get("source")
                ));
            }

            return reranked;
        }
    }

    private static String truncate(String text, int maxLen) {
        return text.length() > maxLen ? text.substring(0, maxLen) + "..." : text;
    }
}
```

## 进阶用法：Instruction 定制

有些 Reranker 模型支持传入 instruction（指令），告诉模型按什么标准来排序。

比如 `Qwen3-Reranker-8B` 就支持这个功能：

```java
/**
 * 带指令的重排序
 */
public static List<RerankResult> rerankWithInstruction(String query,
                                                        List<String> documents,
                                                        String instruction,
                                                        int topN) throws Exception {
    JsonObject body = new JsonObject();
    body.addProperty("model", "Qwen/Qwen3-Reranker-8B");
    body.addProperty("query", query);
    body.add("documents", GSON.toJsonTree(documents));
    body.addProperty("top_n", topN);
    body.addProperty("return_documents", true);
    // 关键：添加自定义指令
    body.addProperty("instruction", instruction);

    // ... 后续调用逻辑相同
}
```

针对不同场景可以设计不同的指令：

**合同审查场景**：
```java
String instruction = "优先排序包含具体法律条文引用、明确期限数字、实际案例的文档";
```

**技术问答场景**：
```java
String instruction = "优先排序包含代码示例、具体配置参数、版本信息的文档";
```

**客服问答场景**：
```java
String instruction = "优先排序直接回答问题的文档，而非背景介绍或流程说明";
```

这个功能在行业问答场景特别有用，可以让 Reranker 按照业务逻辑来排序。

## 元数据过滤：重排序的好搭档

重排序不是万能的，有些情况光靠语义判断还不够，需要结合元数据做硬性过滤。

### 场景1：时效性过滤

法律文书有时效性，2020 年的司法解释可能已经被 2023 年的新规覆盖了。

```java
/**
 * 带元数据过滤的检索+重排序
 */
public List<Document> searchWithMetadataFilter(String query,
                                                LocalDate minDate,
                                                String docType) {
    // 1. 混合检索时加上元数据过滤
    String filterExpr = String.format(
            "publish_date >= '%s' AND doc_type == '%s'",
            minDate, docType
    );

    SearchResp searchResp = client.hybridSearch(HybridSearchReq.builder()
            .collectionName(COLLECTION)
            .searchRequests(List.of(denseReq, sparseReq))
            .ranker(new RRFRanker(60))
            .topK(30)  // 召回多一些，给重排序留余地
            .filter(filterExpr)  // 元数据过滤
            .build());

    // 2. 提取候选文档
    List<String> candidates = extractContents(searchResp);

    // 3. 重排序
    List<RerankResult> reranked = rerank(query, candidates, 5);

    return convertToDocuments(reranked);
}
```

### 场景2：权限过滤

有些文档只有特定角色能看，比如涉密合同、内部政策。

```java
// 根据用户权限过滤
String filterExpr = String.format(
        "access_level <= %d OR created_by == '%s'",
        currentUser.getAccessLevel(),
        currentUser.getUserId()
);
```

### 场景3：分类过滤

用户明确要查某一类文档，比如只看"股权转让"相关的。

```java
// 按文档分类过滤
String filterExpr = "category IN ['股权转让', '公司法', '合同法']";
```

**关键点**：元数据过滤要在召回阶段做，不要在重排序阶段做。因为召回阶段过滤后，候选集就小了，重排序才能在有意义的范围内工作。

## 重排序的性能考量

重排序虽然效果好，但也有成本：

| 指标 | 不加重排序 | 加重排序（30候选） |
|:-----|:-----------|:-------------------|
| 端到端延迟 | ~200ms | ~400ms |
| API 调用成本 | 1次Embedding | 1次Embedding + 1次Rerank |
| Top-3 准确率 | 65% | 85% |

### 什么时候该用重排序

| 场景 | 是否需要重排序 | 原因 |
|:-----|:---------------|:-----|
| 对答案准确率要求高 | 需要 | 重排序显著提升 Top-K 质量 |
| 知识库文档量大 | 需要 | 文档多了，召回排序难以精准 |
| 用户问题复杂多样 | 需要 | 复杂问题需要精细化语义理解 |
| 对延迟极度敏感 | 慎用 | 重排序会增加 100-300ms 延迟 |
| 预算有限 | 慎用 | Reranker API 有额外成本 |
| 知识库小且问题简单 | 可以不用 | 召回质量已经够用 |

### 优化策略

**1. 控制候选数量**

候选太多，重排序慢；候选太少，可能漏掉正确答案。一般 20~50 是比较平衡的范围。

```java
// 根据知识库规模调整
int rerankCandidates = knowledgeBaseSize > 100000 ? 50 : 30;
```

**2. 异步预热**

如果能预判用户可能问什么，可以提前做好召回，等用户真正提问时只需要做重排序。

```java
// 用户输入时预召回
CompletableFuture<List<Document>> prefetch = CompletableFuture.supplyAsync(
        () -> hybridSearch(partialQuery, 50)
);

// 用户按回车时做重排序
List<Document> candidates = prefetch.get();
List<Document> final = rerank(fullQuery, candidates, 5);
```

**3. 轻量级模型兜底**

高峰期可以降级到轻量级 Reranker 或者直接跳过重排序。

```java
if (systemLoad > threshold) {
    // 降级：使用轻量级模型或跳过重排序
    return candidates.subList(0, 5);
}
return rerank(query, candidates, 5);
```

## 完整的检索精排流程

把前面讲的串起来，一个生产级的检索链路是这样的：

```
用户提问
    ↓
问题预处理（改写、扩展）
    ↓
混合检索（向量 + BM25 + RRF融合）
    ↓
元数据过滤（时效性、权限、分类）
    ↓
粗排候选集（Top-30~50）
    ↓
Reranker 精排
    ↓
最终结果（Top-3~5）
    ↓
组装 Prompt + 调用大模型
```

每一步都有其作用：
- **问题预处理**：让用户的问题更适合检索
- **混合检索**：兼顾语义理解和精确匹配
- **元数据过滤**：硬性条件筛选
- **Reranker 精排**：精细化语义排序

## Spring AI 集成示例

如果你用 Spring AI，可以自定义一个带重排序的 Advisor：

```java
/**
 * 带重排序的问答Advisor
 */
public class RerankingQuestionAnswerAdvisor implements RequestResponseAdvisor {

    private final VectorStore vectorStore;
    private final RerankerService rerankerService;
    private final int retrieveTopK;
    private final int rerankTopK;

    @Override
    public AdvisedRequest adviseRequest(AdvisedRequest request, Map<String, Object> context) {
        String userQuery = request.userText();

        // 1. 召回阶段：从向量库检索候选
        List<Document> candidates = vectorStore.similaritySearch(
                SearchRequest.builder()
                        .query(userQuery)
                        .topK(retrieveTopK)  // 召回较多候选
                        .build()
        );

        // 2. 精排阶段：Reranker重排序
        List<Document> reranked = rerankerService.rerank(
                userQuery,
                candidates,
                rerankTopK  // 取Top-K作为最终结果
        );

        // 3. 组装上下文
        String context = reranked.stream()
                .map(Document::getContent)
                .collect(Collectors.joining("\n\n---\n\n"));

        // 4. 构建增强后的Prompt
        String augmentedPrompt = String.format("""
                基于以下参考资料回答用户问题。如果参考资料中没有相关信息，请如实说明。

                参考资料：
                %s

                用户问题：%s
                """, context, userQuery);

        return AdvisedRequest.from(request)
                .withUserText(augmentedPrompt)
                .build();
    }
}

/**
 * Reranker服务封装
 */
@Service
public class RerankerService {

    @Value("${reranker.api.key}")
    private String apiKey;

    @Value("${reranker.model:BAAI/bge-reranker-v2-m3}")
    private String model;

    private final RestTemplate restTemplate = new RestTemplate();

    public List<Document> rerank(String query, List<Document> candidates, int topN) {
        // 调用Reranker API
        RerankRequest request = RerankRequest.builder()
                .model(model)
                .query(query)
                .documents(candidates.stream()
                        .map(Document::getContent)
                        .toList())
                .topN(topN)
                .build();

        RerankResponse response = restTemplate.postForObject(
                "https://api.siliconflow.cn/v1/rerank",
                request,
                RerankResponse.class
        );

        // 按重排序结果重新组织文档
        return response.getResults().stream()
                .map(r -> candidates.get(r.getIndex()))
                .toList();
    }
}
```

## 小结

这篇讲了重排序的核心内容：

1. **为什么需要重排序**：召回阶段追求覆盖面，排序不一定精准；重排序用更强的模型做精细化排序

2. **Bi-Encoder vs Cross-Encoder**：召回用双编码器（快但粗），精排用交叉编码器（慢但准）

3. **实战效果**：重排序能把正确答案从 Top-3 甚至 Top-8 提升到 Top-1，显著提升答案质量

4. **进阶用法**：指令定制、元数据过滤、性能优化

5. **架构建议**：混合检索 + 元数据过滤 + Reranker 精排，是生产环境的推荐方案
