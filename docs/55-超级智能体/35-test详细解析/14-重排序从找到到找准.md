# 重排序：从"找到"到"找准"

## 找到了不等于排对了

上一篇讲了混合检索，向量+关键词双路并行，召回的候选集里确实包含了正确答案。但这里有个容易被忽略的问题：**候选集里有正确答案，不代表正确答案排在最前面**。

举个例子。你在给医疗团队搭一个药品知识库，医生问：`头孢克肟和头孢呋辛在儿童中耳炎治疗中的剂量差异？`

混合检索返回了8个候选结果：

- Top-1：中耳炎的常见致病菌和治疗原则
- Top-2：头孢类抗生素的分类和代际特点
- Top-3：头孢克肟儿童用药剂量表
- Top-4：**头孢克肟与头孢呋辛在儿童中耳炎中的对比用药方案**（这才是最佳答案）
- Top-5：头孢呋辛的药代动力学参数
- ...

最佳答案在Top-4，但如果你只取Top-3喂给大模型，医生就拿不到想要的对比信息。

问题出在哪？召回阶段追求的是"尽可能把相关的都找出来"（高召回率），但排序精度有限。最终给大模型的上下文窗口很小，真正关键的是Top-3或Top-5的排序是否正确。

:::info 重排序的定位
重排序（Reranking）是检索链路的第二阶段，专门解决"召回了但排序不精准"的问题。它用更强大的模型对候选集逐个打分，代价是速度较慢，所以只对召回的少量候选（通常20-50个）执行。
:::

## 两阶段检索：快召回 + 慢精排

为什么不直接用最精准的模型做检索？因为太慢了。

假设知识库有100万个文档块，用户提问时，你需要把100万个块逐个和query做精细比对——这需要100万次模型推理，延迟和成本都不可接受。

所以工程上一定是两阶段策略：

1. **粗召回**（向量检索/BM25/混合检索）：快速从100万个块中筛出Top-20或Top-50，延迟低、覆盖面广
2. **精排序**（Reranker模型）：对这20-50个候选逐个精细打分，延迟可接受、精度高

这就是"快召回 + 慢精排"的核心思想。

## Bi-Encoder vs Cross-Encoder

理解重排序的关键是搞清楚两种编码器的区别。

### Bi-Encoder（双编码器）——召回阶段用的

Query和Document分别独立编码成向量，然后计算向量距离。这就是Embedding模型的工作方式。

```
Query    → [Encoder] → Query向量  ─┐
                                    ├→ cosine(Q, D) = 0.85
Document → [Encoder] → Doc向量   ─┘
```

优点：速度快。Document向量可以提前算好存起来，查询时只需要编码Query。

缺点：精度有限。Query和Document是独立编码的，模型看不到它们之间的交互关系。比如"头孢克肟与头孢呋辛的剂量差异"这个query，Bi-Encoder分别理解了query和document，但无法捕捉"query问的是两种药的对比，document里恰好有这个对比"这种细粒度的匹配关系。

### Cross-Encoder（交叉编码器）——重排序用的

把Query和Document拼接在一起，一起输入模型，模型能看到完整的交互，直接输出一个相关性分数。

```
[CLS] Query [SEP] Document [SEP] → [Encoder] → 相关性分数 0.95
```

优点：精度高。模型能同时看到query和document的每一个词，捕捉细粒度的语义关系。

缺点：速度慢。每个(query, document)对都要过一遍模型，不能提前计算。

这就是为什么Cross-Encoder只能用在重排序阶段——候选集已经很小了（20-50个），可以接受慢一点的速度，换取更高的精度。

## 主流Reranker模型对比

| 模型 | 特点 | 中文效果 | API可用性 | 适用建议 |
| :--- | :--- | :--- | :--- | :--- |
| BAAI/bge-reranker-v2-m3 | 轻量、中文效果稳定 | 好 | SiliconFlow等平台 | 预算敏感且要中文效果 |
| Qwen/Qwen3-Reranker-8B | 长文本能力强，支持instruction定制 | 很好 | SiliconFlow等平台 | 复杂意图排序、行业问答 |
| Cohere rerank-v4.0 | 商业API成熟 | 一般 | Cohere官方API | 海外或多语言场景 |
| jina-reranker-v2-base | 多语言支持好 | 好 | Jina AI官方API | 跨语言场景 |

对于中文RAG场景，推荐BAAI/bge-reranker-v2-m3（轻量快速）或Qwen/Qwen3-Reranker-8B（效果更好，支持自定义指令）。

## Java代码实战：调用Reranker API

### 基础版：调用SiliconFlow Rerank接口

```java
public class RerankService {

    private static final String API_KEY = "你的API Key";
    private static final String RERANK_URL =
        "https://api.siliconflow.cn/v1/rerank";
    private static final String MODEL = "BAAI/bge-reranker-v2-m3";
    private static final Gson GSON = new Gson();
    private static final OkHttpClient HTTP = new OkHttpClient();

    public static class RerankItem {
        public int index;
        public double score;
        public String text;
    }

    public List<RerankItem> rerank(String query,
            List<String> candidates, int topN) throws IOException {
        JsonObject body = new JsonObject();
        body.addProperty("model", MODEL);
        body.addProperty("query", query);
        body.add("documents", GSON.toJsonTree(candidates));
        body.addProperty("top_n", topN);
        body.addProperty("return_documents", true);

        Request request = new Request.Builder()
                .url(RERANK_URL)
                .addHeader("Authorization", "Bearer " + API_KEY)
                .addHeader("Content-Type", "application/json")
                .post(RequestBody.create(
                    GSON.toJson(body),
                    MediaType.parse("application/json")))
                .build();

        try (Response response = HTTP.newCall(request).execute()) {
            if (!response.isSuccessful()) {
                throw new RuntimeException(
                    "rerank调用失败，HTTP=" + response.code());
            }

            JsonObject resp = GSON.fromJson(
                response.body().string(), JsonObject.class);
            JsonArray results = resp.getAsJsonArray("results");

            List<RerankItem> items = new ArrayList<>();
            for (int i = 0; i < results.size(); i++) {
                JsonObject one = results.get(i).getAsJsonObject();
                RerankItem item = new RerankItem();
                item.index = one.get("index").getAsInt();
                item.score = one.get("relevance_score").getAsDouble();
                item.text = one.getAsJsonObject("document")
                    .get("text").getAsString();
                items.add(item);
            }

            items.sort(Comparator.comparingDouble(
                (RerankItem x) -> x.score).reversed());
            return items;
        }
    }
}
```

### 进阶版：Qwen3-Reranker支持自定义指令

Qwen3-Reranker-8B支持`instruction`参数，可以告诉模型按什么标准排序：

```java
JsonObject body = new JsonObject();
body.addProperty("model", "Qwen/Qwen3-Reranker-8B");
body.addProperty("query", query);
body.add("documents", GSON.toJsonTree(candidates));
body.addProperty("top_n", topN);
body.addProperty("return_documents", true);
// 自定义排序指令
body.addProperty("instruction",
    "优先排序包含具体剂量数据和对比信息的文档");
```

这在行业问答场景很实用——比如医疗场景可以指定"优先排序包含临床数据的文档"，法律场景可以指定"优先排序包含具体法条引用的文档"。

### 完整流程：混合检索 + 重排序

```java
@GetMapping("/search")
public String search(@RequestParam String query) throws Exception {
    // 1. 混合检索召回候选集
    SearchResp hybridResp = hybridSearch(client, query);
    List<String> candidates = extractTexts(hybridResp);

    // 2. 重排序
    List<RerankItem> reranked =
        rerankService.rerank(query, candidates, 5);

    // 3. 取Top-5构建上下文
    String context = reranked.stream()
            .map(item -> item.text)
            .collect(Collectors.joining("\n\n---\n\n"));

    // 4. 调用大模型生成回答
    String prompt = """
        基于以下参考文档回答用户问题。
        如果文档中没有相关信息，请说明。

        参考文档：
        %s

        用户问题：%s
        """.formatted(context, query);

    return chatClient.prompt(prompt).call().content();
}
```

### 使用阿里云DashScope的Reranker

如果你用的是阿里云的模型服务，调用方式略有不同：

```java
private List<String> rerankWithDashScope(List<String> documents,
        String query, int topK) throws Exception {
    String url = "https://dashscope.aliyuncs.com/api/v1"
        + "/services/rerank/text-rerank/text-rerank";

    HttpHeaders headers = new HttpHeaders();
    headers.set("Authorization", "Bearer " + apiKey);
    headers.setContentType(MediaType.APPLICATION_JSON);

    Map<String, Object> requestBody = Map.of(
        "model", "qwen3-rerank",
        "input", Map.of("query", query, "documents", documents),
        "parameters", Map.of(
            "return_documents", true,
            "top_n", topK
        )
    );

    ResponseEntity<Map> response = restTemplate.postForEntity(
        url, new HttpEntity<>(requestBody, headers), Map.class);

    Map<String, Object> output =
        (Map<String, Object>) response.getBody().get("output");
    List<Map<String, Object>> results =
        (List<Map<String, Object>>) output.get("results");

    return results.stream()
            .map(item -> (String) ((Map<String, Object>)
                item.get("document")).get("text"))
            .collect(Collectors.toList());
}
```

## 重排序的效果验证

用同一个query对比重排序前后的结果差异：

**Query**：头孢克肟和头孢呋辛在儿童中耳炎治疗中的剂量差异

| 阶段 | Top-1 | Top-2 | Top-3 |
| :--- | :--- | :--- | :--- |
| 混合检索（未重排） | 中耳炎治疗原则 | 头孢类抗生素分类 | 头孢克肟剂量表 |
| 混合检索 + Rerank | **头孢克肟与头孢呋辛对比用药方案** | 头孢克肟剂量表 | 头孢呋辛药代动力学 |

重排序把最相关的对比文档从Top-4提升到了Top-1，同时把两种药物各自的详细信息也排到了前面。

重排序的价值不在于多找几个结果，而在于**把真正该进上下文窗口的那几个排到最前面**。

## 检索参数调优指南

### 推荐起始值

| 参数 | 建议值 | 调优方向 |
| :--- | :--- | :--- |
| Dense topK | 20 | 漏召回就加大，延迟高就减小 |
| Sparse topK | 20 | query含精确关键词多时可升到40 |
| RRF k | 60 | 两路结果波动大时保持60 |
| Rerank候选数 | 30 | 精度不够可升到50，注意延迟 |
| 最终返回K | 5 | 结合大模型上下文窗口调整 |

### 调优顺序很重要

**先调召回覆盖，再调排序精度**。

很多团队一上来就调Reranker，结果其实是召回阶段已经漏掉了关键文档块，后面怎么重排都救不回来。正确的顺序：

1. 先看召回覆盖率（Recall@20），确保相关的块都被召回了
2. 再看排序精度（MRR、nDCG@10），优化Top-K的排序质量
3. 最后看业务指标（人工标注准确率、用户追问率）

:::caution Reranker的语义偏向
Cross-Encoder本质上是语义匹配模型，它可能更倾向于提升语义相似度高的文档排序，从而弱化那些关键词匹配度高但语义表达不强的结果。在混合检索场景中，如果发现Reranker把关键词精确匹配的结果排低了，可以考虑调整Reranker的候选集构成，或者在RRF融合后再做Rerank。
:::

## 四种检索策略的完整对比

| 策略 | 召回覆盖 | Top-3精度 | 延迟 | 成本 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 纯向量检索 | 高 | 中 | 低 | 低 | 数据量小，query以自然语言为主 |
| 纯BM25 | 中 | 中 | 低 | 低 | query包含大量精确关键词 |
| 混合检索 | 高 | 高 | 中 | 中 | 大多数RAG场景的推荐方案 |
| 混合检索 + Rerank | 最高 | 最高 | 中高 | 中高 | 对答案准确率要求高的场景 |

## 小结

重排序是RAG检索链路中投入产出比很高的环节：

- 它解决的是"召回了但排序不精准"的问题，用Cross-Encoder对候选集精细打分
- 工程上采用"快召回 + 慢精排"的两阶段策略，兼顾速度和精度
- 中文场景推荐BAAI/bge-reranker-v2-m3或Qwen/Qwen3-Reranker-8B
- 调优时先保证召回覆盖率，再优化排序精度
