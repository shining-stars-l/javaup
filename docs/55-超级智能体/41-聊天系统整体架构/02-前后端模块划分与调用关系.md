# 前后端模块划分与调用关系

这篇文档聚焦后端部分，把 Super Agent 的 Maven 模块划分、聊天业务的包结构、各层核心类的职责和调用关系都理清楚。看完之后，你拿到任何一个类名，都能快速定位它在整个架构中的位置和作用。

## Maven 模块总览

Super Agent 后端采用多模块 Maven 结构，每个模块有明确的职责边界：

```plantuml
@startuml
skinparam backgroundColor #FAFBFC
skinparam defaultFontName "Microsoft YaHei"
skinparam defaultFontSize 13
skinparam shadowing false
skinparam roundCorner 10
skinparam packageStyle rectangle
skinparam ArrowColor #5B8DEF
skinparam ArrowThickness 1.5

skinparam package {
  BackgroundColor #FFFFFF
  BorderColor #D0D7DE
  FontColor #1F2328
}

skinparam component {
  BackgroundColor #EBF3FF
  BorderColor #5B8DEF
  FontColor #1F2328
}

package "super-agent (父工程)" {

  package "super-agent-common" as common {
    component "common-frame" as cf
    component "common-web" as cw
    note bottom of cf
      枚举、工具类、通用响应
      ChatQueryMode、ChatTurnStatus 等
    end note
  }

  package "super-agent-id-generator-framework" as idgen {
    component "ID 生成器" as ig
    note bottom of ig
      分布式 ID 生成
    end note
  }

  package "super-agent-redisson-framework" as redis {
    component "分布式锁" as rl
    component "重复执行限制" as rel
    component "Redis 租约" as lease
    note bottom of lease
      RedisLeaseManager
      会话并发控制的基础
    end note
  }

  package "super-agent-business" as biz {
    component "super-agent-business-chat" as chat
    note bottom of chat
      聊天系统的全部业务代码
      Controller / Service / RAG / 文档管理
    end note
  }
}

chat --> cf : 使用枚举和工具类
chat --> cw : 使用 Web 基础设施
chat --> ig : 生成会话/轮次 ID
chat --> lease : 会话分布式租约

@enduml
```

| 模块 | 职责 |
| :--- | :--- |
| `super-agent-common` | 通用基础设施：枚举定义（`ChatQueryMode`、`ChatTurnStatus`）、工具类、统一响应封装 |
| `super-agent-id-generator-framework` | 分布式 ID 生成，为会话和轮次提供全局唯一标识 |
| `super-agent-redisson-framework` | Redis 相关能力：分布式锁、重复执行限制、**会话租约管理**（`RedisLeaseManager`） |
| `super-agent-business-chat` | 聊天系统的全部业务代码，是最核心的模块 |
