# 执行器体系与模式分发

准备阶段确定了"该用什么模式回答"之后，就轮到执行器上场了。执行器体系用的是经典的策略模式：一个接口、一个注册表、五个具体实现，各管各的。

## 设计模式

整体结构很清晰：

```
ConversationExecutor（接口）
├── RagChatExecutor          → RETRIEVAL 模式
├── GraphOnlyExecutor        → GRAPH_ONLY 模式
├── GraphThenEvidenceExecutor → GRAPH_THEN_EVIDENCE 模式
├── ReactAgentExecutor       → REACT_AGENT 模式
└── ClarificationExecutor    → CLARIFICATION 模式
```

`ConversationExecutorRegistry` 负责把它们按 `ExecutionMode` 注册好，运行时根据执行计划里的模式直接取出对应的执行器。

## 接口与注册表

### ConversationExecutor（接口）

**包路径：** `org.javaup.ai.chatagent.rag.executor`

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `mode()` | `ExecutionMode` | 声明自己负责哪种模式 |
| `execute(TaskInfo)` | `Flux<String>` | 执行并返回流式输出 |

### ConversationExecutorRegistry

**包路径：** `org.javaup.ai.chatagent.rag.executor`

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `ConversationExecutorRegistry(List<ConversationExecutor>)` | — | 构造时自动发现所有执行器 Bean，按 mode 注册到 EnumMap |
| `get(ExecutionMode)` | `ConversationExecutor` | 根据模式取执行器，找不到抛 IllegalStateException |
