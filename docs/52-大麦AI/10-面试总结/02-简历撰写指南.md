## 写简历的基本原则
简历不是流水账，是你能力的广告。写的时候要站在面试官的角度想：如果我是面试官，看到这份简历，会觉得这个人怎么样？

几个核心原则：

1. **突出重点**：不是什么都往上写，要把最能体现能力的东西放在显眼的位置
2. **量化结果**：能用数字说话的就用数字，"提升效率"不如"响应时间从30分钟缩短到2分钟"
3. **技术深度**：不要只罗列技术名词，要体现你对这些技术的理解和实践
4. **真实可靠**：别瞎编，面试的时候问几个细节就露馅了

**大麦AI智能助手系统**

**项目介绍**：基于Spring AI框架开发的购票系统智能服务平台，集成购票咨询助手、运维分析助手、规则知识库三大核心能力，实现用户咨询自动应答和故障智能排查，显著提升服务效率。

**技术栈**：Spring Boot、Spring AI、Vue 3、DeepSeek、RAG、Function Call、MCP、SSE

**个人职责**：

+ **AI对话系统设计与开发**：基于Spring AI框架实现多场景ChatClient，包括购票咨询、运维分析、知识问答三类智能助手。设计Advisor链式架构，实现对话历史管理、会话标题生成、消息记忆等功能模块的解耦和复用。
+ **Function Call工具体系建设**：设计并实现购票业务工具集，包括节目推荐、节目查询、票档查询、订单创建等功能。通过@Tool注解定义工具函数，实现大模型根据用户意图自动选择工具、解析参数、执行调用的完整链路。
+ **RAG知识库系统开发**：实现规则文档的向量化存储和检索能力。使用MarkdownDocumentReader解析文档，通过text-embedding-v3模型生成向量，配置QuestionAnswerAdvisor实现检索增强生成，知识检索topK=8，相似度阈值0.3。

+ **流式对话实现**：基于SSE技术实现AI回复的流式输出，解决大模型响应延迟导致的用户等待问题。前端使用Flux处理流式数据，实现逐字渲染效果。

**项目亮点**：

+ 购票助手承接日常咨询量的80%以上，显著减轻客服压力
+ 运维助手将故障排查时间从平均15分钟缩短到2分钟以内
+ MCP工具服务架构支持工具的即插即用和独立扩展

这种写法适合想突出技术深度的情况。

---

**智能购票与运维助手平台**

**项目介绍**：为大麦购票系统设计开发的AI智能服务平台，包含购票咨询、运维分析、知识问答三大功能模块，采用Spring AI + MCP + RAG技术栈，实现了从用户咨询到故障排查的全场景AI赋能。

**技术栈**：Spring Boot、Spring AI、DeepSeek/通义千问、Vue 3、Elasticsearch、Prometheus、MCP Protocol

**技术实现与亮点**：

+ **多模型协同架构**：对接DeepSeek和通义千问两类模型，DeepSeek负责对话推理，通义千问的text-embedding-v3负责文档向量化。通过Spring AI的统一接口实现模型切换透明化。
+ **Function Call工具调用**：使用@Tool/@ToolParam注解定义业务工具，实现节目查询、票档查询、订单创建等核心功能。大模型根据用户意图自主选择工具链，支持多工具组合调用完成复杂业务流程。
+ **RAG检索增强生成**：基于向量相似度检索实现规则文档的智能问答。文档分块使用语义段落切分，向量维度1024，检索配置topK=8、similarityThreshold=0.3，prompt层面增加"禁止编造"约束防止幻觉。
+ **MCP协议工具服务化**：将日志查询、监控查询能力封装为独立MCP服务。日志服务提供getServiceList、searchLogsByKeyword、getLogsByTraceId等7个工具；监控服务提供getJvmMemory、getCpuMetrics、getServiceHealthOverview等6个工具。
+ **Advisor链式架构**：设计ChatTypeHistoryAdvisor、ChatTypeTitleAdvisor、MessageChatMemoryAdvisor三层Advisor，分别处理会话历史持久化、会话标题生成、消息窗口记忆，通过order属性控制执行顺序，实现功能解耦。
+ **SSE流式输出优化**：使用Flux响应式流处理AI回复，配合前端逐字渲染实现打字机效果。解决大模型推理延迟导致的用户体验问题，首字节响应时间优化到1秒以内。

## 几个注意事项
### 技术名词要准确
别把技术名词写错了，这是减分项：

+ ❌ Spring-AI → ✅ Spring AI
+ ❌ function call → ✅ Function Call（专有名词首字母大写）
+ ❌ rag → ✅ RAG（缩写全大写）
+ ❌ MCP协议 → ✅ MCP（Model Context Protocol）

### 数字要具体但要真实
"提升效率"不如"响应时间缩短90%"，但数字要真实可解释。

面试官可能会问："这个90%是怎么测出来的？"

你得能回答："我们统计了上线前一个月的平均故障排查时间是15分钟，上线后通过日志统计发现平均是2分钟左右，所以大概是7倍的提升。"

编的数字经不起追问，真实的数字你能讲出细节。

### 职责要体现你做了什么
不要写成需求文档，要体现你的贡献：

+ ❌ "系统支持多轮对话" → ✅ "设计并实现MessageWindowChatMemory管理对话历史，支持20轮上下文记忆"
+ ❌ "实现了RAG功能" → ✅ "基于QuestionAnswerAdvisor实现RAG知识库，调优topK和相似度阈值参数"

### 亮点要能展开
简历上写的每一个亮点，你都要准备好展开讲的内容。

写"实现了MCP工具服务"，面试官可能问：

+ MCP是什么？
+ 为什么要用MCP而不是直接写在主服务里？
+ 工具服务提供了哪些具体功能？
+ 工具是怎么被大模型调用的？

如果这些问题你答不上来，这个亮点就变成了"减分项"——说明你只是知道这个词，没有真正理解和实践。

## 简历之外的准备
简历只是敲门砖，面试才是正题。

### 准备好项目介绍的说辞
1-2分钟能把项目讲清楚：背景→方案→技术→效果。不要上来就讲技术细节，先让面试官知道这个项目是干什么的、解决什么问题。

### 准备好技术深度的问题
简历上写的每个技术点，都要准备好被追问。RAG的原理是什么？Function Call是怎么实现的？SSE和WebSocket有什么区别？MCP协议是什么？

这些问题的答案在《面试热门问题》文档里都有，要能自己消化了讲出来，不是死记硬背。

### 准备好困难和挑战的故事
"你做这个项目遇到过什么困难？"是高频问题。

准备1-2个真实的困难：

+ 遇到了什么问题
+ 你是怎么分析的
+ 你是怎么解决的
+ 最后效果怎么样

比如RAG检索效果不好的问题、prompt调优的过程、MCP服务设计的考量等等。

### 准备好自己的思考
"为什么选这个技术而不是那个？"体现的是你的技术判断力。

+ 为什么用Spring AI不用LangChain？
+ 为什么用SSE不用WebSocket？
+ 为什么把工具做成MCP服务？

这些选择背后的理由，要能讲清楚，说明你不是盲目跟风，而是有自己的思考。
