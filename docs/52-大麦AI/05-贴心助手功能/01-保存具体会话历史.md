## 创建ChatClient
在实现此功能的第一个步骤就是要把ChatClient创建出来

org.javaup.ai.config.DaMaiAiAutoConfiguration

```java
@Bean
public ChatClient assistantChatClient(DeepSeekChatModel model) {
    return ChatClient
            .builder(model)
            .defaultSystem(DaMaiConstant.DA_MAI_SYSTEM_PROMPT)
            .defaultAdvisors(
                    new SimpleLoggerAdvisor())
            )
            .build();
}
```

为了和上一个例子做区分，这里创建出的名字叫 **assistantChatClient**

## 创建Controller实现对话功能
```java
@RequestMapping(value = "/chat", produces = "text/html;charset=utf-8")
public Flux<String> chat(@RequestParam("prompt") String prompt) {
    // 请求模型
    return assistantChatClient.prompt()
            .user(prompt)
            .stream()
            .content();
}
```

到这里，就把简单的对话完成了，但是到这里是远远不够的，因为此时的ai并不具备联系上下文的功能。

## 什么是联系上下文？
当你和 AI 聊天时，AI 需要知道：

+ 你之前问了什么
+ 你现在问的和之前的有没有关联

### 场景描述
用户想了解一款手机，接着问价格，再问优惠。

### 不具备联系上下文的特点：
#### 第一次请求：
用户：iPhone 15 怎么样？  
AI：iPhone 15 拥有强大的 A16 芯片，续航优秀，拍照效果出色。

#### 第二次请求：
用户：多少钱？  
AI：抱歉，您能告诉我您指的是哪款手机吗？

#### 第三次请求：
用户：有优惠吗？  
AI：请问您具体指的哪款产品？

👉 每次对话 AI 都不知道用户在聊 iPhone 15，体验很差。

### ChatId的作用
所以联系上下文功能是必须要有的！而SpringAI也是提供了此功能，在进行和ai对话时，只要传入一个id， 通常是用来**标识一次连续的对话会话**，它的核心作用是：  
✅ 保持上下文  
✅ 让 AI 记住历史对话，进行多轮对话的逻辑关联

SpringAI会自动此id和本次对话进行关联并保存。当查询时，就可以根据此id从SpringAI中查询对话历史内容了，在此项目中我把这个id起名为**chatId**

### 使用 chatId（保持上下文）
#### 第一次请求：
用户：iPhone 15 怎么样？ （chatId: 123）  
AI：iPhone 15 拥有强大的 A16 芯片，续航优秀，拍照效果出色。

#### 第二次请求：
用户：多少钱？ （chatId: 123）  
AI：iPhone 15 的售价约为 5999 元起。

#### 第三次请求：
用户：有优惠吗？ （chatId: 123）  
AI：目前 iPhone 15 正在进行优惠活动，最高可减 500 元。

👉 AI 自动关联了上下文，用户体验非常流畅。

# 修改创建ChatClient
为了让创建出的ChatClient具有保存上下文的功能，要对创建ChatClient的过程进行改造

```java
@Bean
public ChatClient assistantChatClient(DeepSeekChatModel model, ChatMemory chatMemory) {
    return ChatClient
            .builder(model)
            .defaultSystem(DaMaiConstant.DA_MAI_SYSTEM_PROMPT)
            .defaultAdvisors(
                    new SimpleLoggerAdvisor(),
                    MessageChatMemoryAdvisor.builder(chatMemory).build()
            )
            .defaultTools(aiProgram)
            .build();
}
```

加了 **MessageChatMemoryAdvisor.builder(chatMemory).build() **这一行，就具备保存上下文的功能了。

chatMemory 就是实现保存的关键所在，默认是保存到内存中的，而项目为了真实，肯定是要保存到数据库中的。所以要再做一些额外的功能

## **chatMemory**
先看一下chatMemory的结构

```java
public final class MessageWindowChatMemory implements ChatMemory {

	private static final int DEFAULT_MAX_MESSAGES = 20;

	private final ChatMemoryRepository chatMemoryRepository;

	private final int maxMessages;

	private MessageWindowChatMemory(ChatMemoryRepository chatMemoryRepository, int maxMessages) {
		Assert.notNull(chatMemoryRepository, "chatMemoryRepository cannot be null");
		Assert.isTrue(maxMessages > 0, "maxMessages must be greater than 0");
		this.chatMemoryRepository = chatMemoryRepository;
		this.maxMessages = maxMessages;
	}

	@Override
	public void add(String conversationId, List<Message> messages) {
		Assert.hasText(conversationId, "conversationId cannot be null or empty");
		Assert.notNull(messages, "messages cannot be null");
		Assert.noNullElements(messages, "messages cannot contain null elements");

		List<Message> memoryMessages = this.chatMemoryRepository.findByConversationId(conversationId);
		List<Message> processedMessages = process(memoryMessages, messages);
		this.chatMemoryRepository.saveAll(conversationId, processedMessages);
	}

	@Override
	public List<Message> get(String conversationId) {
		Assert.hasText(conversationId, "conversationId cannot be null or empty");
		return this.chatMemoryRepository.findByConversationId(conversationId);
	}

	@Override
	public void clear(String conversationId) {
		Assert.hasText(conversationId, "conversationId cannot be null or empty");
		this.chatMemoryRepository.deleteByConversationId(conversationId);
	}
```



能看到真正实现保存的操作是靠 chatMemoryRepository 来执行的

很简单，只要引入对应的依赖就可以了

## 引入数据库保存需要的依赖
```xml
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-chat-memory-repository-jdbc</artifactId>
</dependency>
```

spring-ai-starter-model-chat-memory-repository-jdbc 这个依赖引入就自动切换到数据库保存了

除了引入依赖外，配置也要进行添加

## 添加配置
```yaml
spring:
  application:
    name: damai-ai
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/damai_ai?serverTimezone=Asia/Shanghai&useSSL=false&useUnicode=true&characterEncoding=utf-8&zeroDateTimeBehavior=convertToNull&transformedBitIsBoolean=true&tinyInt1isBit=false&allowPublicKeyRetrieval=true&allowMultiQueries=true&useServerPrepStmts=false
    username: root
    password: root
  ai:
    chat:
      memory:
        repository:
          jdbc:
            initialize-schema: always
            platform: mariadb
```

这样就可以将chatId和会话内容保存到数据库中了，并且表是自动创建的

# 修改对话功能
```java
@RequestMapping(value = "/chat", produces = "text/html;charset=utf-8")
public Flux<String> chat(@RequestParam("prompt") String prompt,
                         @RequestParam("chatId") String chatId) {
    // 请求模型
    return assistantChatClient.prompt()
    .user(prompt)
    .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, chatId))
    .stream()
    .content();
}
```

在chat方法中，还要新加 **chatId** 参数，此参数是通过前端传入的，每开启一个新的对话，就会传入新的chatId

除了新增一个chatId入参外，对于 assistantChatClient 要额外加一个 **.advisors(a -> a.param(ChatMemory.CONVERSATION_ID, chatId))**，这样就会把chatId和对话中的每次聊天进行关联了
